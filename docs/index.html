ぽちっとストアを動かそうGitHub・Linux・MySQL・Python を一本道で体験する

小さなECサイトを手元で動かして、商品を登録し、買って、その注文がデータベースに入るところまで見届けます。ターミナルが初めてでも大丈夫。上から順に進めてください。

全体の構成図

今日あつかうものが、どこにあって、どうつながっているか。注文は ①→④ の順に流れます。

  1. 1注文者がストアで商品を選び、「注文を確定する」を押す
  2. 2アプリが注文を受け取り、INSERT の SQL を作る
  3. 3SQL が SSHトンネルを通って、クラウドの MySQL に保存される
  4. 4店長が管理画面を開くと、MySQL から注文を読み出して表示する

今日の構成

お店（アプリ）は あなたのPCの中 で動き、注文者も店長もあなた自身。データだけがクラウドにあります。

本物のECサイトでは

お店（アプリ）も クラウドのサーバ に置かれ、お客さんは世界中からインターネット経由でやってきます。データの置き場は今日と同じ、データベースです。

道具をそろえる

目安 30分勉強会の前にやっておく

MISSION4つの道具をPCに入れて、ターミナルで「入ったよ」と返事をもらう。

  1. ターミナル（PowerShell）を開く

    キーボードの Windowsキー を押して「terminal」と打ち、ターミナル を開きます。黒か青の画面に文字が出ていればOK。これから何度も使う「司令室」です。

    このページの見方：コマンドの箱の上に「どこで打つか」が書いてあります。● 自分のPC と書いてあれば、このターミナルに打ちます。

  2. Git を入れる

    git-scm.com から「Git for Windows」をダウンロードしてインストール。途中の質問は全部そのまま「Next」で大丈夫です。

  3. Python を入れる

    python.org から Python 3.12 以降をダウンロードしてインストールします。

    ここが一番の落とし穴：インストーラの最初の画面の下にある 「Add python.exe to PATH」に必ずチェック を入れてから「Install Now」を押してください。忘れると、あとで python が見つからないと言われます。

  4. VS Code と A5M2 を入れる

    • VS Code：ソースを読んだり書いたりするエディタ
    • A5:SQL Mk-2（A5M2）：データベースを画面で見られるツール

  5. GitHub アカウントを作る

    github.com で無料アカウントを作ります。作ったら、上の「あなたの情報」にユーザー名を入れておきましょう。

  6. ターミナルを一度閉じて開き直し、点呼をとる

    インストールしたものは、ターミナルを開き直さないと認識されません。開き直したら1行ずつ打って、Enter を押します。

    git --version
    python --version
    ssh -V
    こんな返事が来ればOK（数字は違っていて大丈夫）
    git version 2.47.0.windows.1
Python 3.12.7
OpenSSH_for_Windows_9.5p1, LibreSSL 3.8.2

  7. Git に名前を教える

    Git に「誰が変更したか」を記録してもらうための設定です。最初に1回だけやります。

    git config --global user.name "GitHubユーザー名"
    git config --global user.email "GitHubに登録したメールアドレス"

クリア条件：3つのコマンドすべてにバージョンが返ってきた。

GitHub1

ソースを自分のものにする

目安 20分git clone / remote / push

MISSION講師のリポジトリからソースを持ってきて、自分のGitHubに引っ越しさせる。

  1. 作業用のフォルダに移動する

    cd は「その場所へ移動する」コマンドです。ドキュメントフォルダに移動しましょう。

    cd ~\Documents

  2. ソースを丸ごとコピーしてくる（clone）

    git clone https://github.com/講師のアカウント/potchi-store.git
    cd potchi-store
    ls
    中身はこんな構成です
    potchi-store/
├── app.py             ← アプリの入口。URLごとの処理が書いてある
├── db.py              ← MySQLにつなぐ係
├── templates/
│   ├── shop/          ← お客さん向けの画面（HTML）
│   └── admin/         ← 管理画面（HTML）
├── static/style.css   ← 見た目
├── sql/               ← テーブルを作るSQL（講師用）
├── scripts/           ← 受講者の追加など（講師用）
├── README.md          ← このリポジトリの説明書
├── requirements.txt   ← 必要なライブラリの一覧表
├── .env.example       ← 接続設定のひな形
└── .gitignore         ← GitHubに上げないものリスト

  3. GitHub に自分の空っぽのリポジトリを作る

    ブラウザで GitHub を開き、右上の ＋ →「New repository」。

    • Repository name：potchi-store
    • Public / Private：どちらでもOK
    • 「Add a README file」などは 何もチェックしない（空っぽで作るのがコツ）

  4. 送り先（remote）を付け替える

    今のままだと、このソースは「講師のリポジトリ」に紐づいています。行き先を自分のリポジトリに変えます。

    git remote -v
    git remote rename origin upstream
    git remote add origin https://github.com/GitHubユーザー名/potchi-store.git
    git remote -v
    なぜ？ origin は「自分の送り先」、upstream は「元ネタ（講師）」という名前の付け方が定番です。こうしておくと、講師がソースを更新したときにも取り込めます。

  5. 自分のGitHubに上げる（push）

    git push -u origin main

    初回はブラウザが開いて GitHub へのログインを求められます。許可すれば送信が始まります。終わったら、GitHub の自分のリポジトリを再読み込みしてみましょう。

クリア条件：自分のGitHubの potchi-store にファイルが並んでいる。

Linux2

サーバに乗り込む

目安 25分ssh / 基本コマンド

MISSION自分のPCから、遠くにあるLinuxサーバにログインして、中を歩き回る。

  1. 鍵ファイルを置く

    サーバに入るための「鍵」のファイル potchi_key を講師から受け取ります。まず鍵の置き場所を作ります。

    mkdir ~\.ssh

    エクスプローラーで C:\Users\（あなたの名前）\.ssh を開き、受け取った potchi_key をその中に入れてください（「すでに存在します」と出たら、そのまま進めてOK）。

    鍵は参加者だけのもの：鍵は全員共通ですが、パスワードと同じものです。社外の人に渡したり、GitHub に上げたりしないでください。

  2. ssh でログインする

    ssh -i ~\.ssh\potchi_key 受講者ID@サーバIP

    初回だけ「本当に接続しますか？」と英語で聞かれるので、yes と打って Enter。

    左側の表示がこう変わったら、あなたはもうサーバの中です
    受講者ID@potchi-server:~$
    ここから先は別世界：この画面に打つコマンドは、あなたのPCではなく Google のデータセンターにあるコンピュータ で実行されます。箱の色が ● Linuxサーバ に変わるのが合図です。

  3. コマンド練習：自分の居場所を知る

    1つずつ打って、何が返ってくるか見てみましょう。

    • whoami

      私は誰？ ユーザー名が出ます。今日は全員が同じ student で入っています。

    • pwd

      今どこ？ 今いるフォルダの場所を表示します。

    • ls

      ここに何がある？ ファイルの一覧です。

    • ls -la

      隠しファイルも含めて、詳しく一覧表示します。

  4. コマンド練習：作って、書いて、読む

    サーバの中は全員で共有しているので、自分の名前のフォルダを作って、その中で練習します。

    • mkdir GitHubのユーザー名

      自分の名前のフォルダを作ります（GitHubのユーザー名を使います）。

    • cd GitHubのユーザー名

      その中に移動します。

    • echo "hello potchi" > hello.txt

      文字をファイルに書き込みます。

    • cat hello.txt

      ファイルの中身を表示します。

    • cd ..

      1つ上のフォルダに戻ります。

  5. コマンド練習：サーバの健康診断

    • cat /etc/os-release

      このサーバのOS（Ubuntu）を確認します。

    • free -h

      メモリの量。無料のサーバなので約1GBしかありません。

    • df -h

      ディスクの空き容量です。

    • systemctl status mysql

      MySQLが動いているか確認します。緑の active (running) が出たら元気です。q で抜けます。

    便利ワザ：キーボードの ↑ で、さっき打ったコマンドが出てきます。Tab を押すと、ファイル名を途中まで打ったところで残りを補完してくれます。

クリア条件：ls で、みんなのフォルダの中に自分のフォルダが見える。cat 自分のフォルダ/hello.txt で自分が書いた文字が表示された。（ログインしたまま次へ進みます）

MySQL3

データベースをのぞく

目安 20分mysql / SELECT

MISSIONLinuxの中にいるMySQLに話しかけて、ストアの商品をSQLで取り出す。

  1. MySQL に入る

    Linuxサーバにログインしたまま打ちます。パスワードを聞かれたら、講師から配られたものを入力（画面には何も表示されませんが、ちゃんと入力されています）。

    mysql -u 受講者ID -p
    プロンプトが mysql> になったら成功
    Welcome to the MySQL monitor.  Commands end with ; or \g.
mysql>
    入れ子になっている：今のあなたは「PC → Linux → MySQL」と、箱の中の箱の中にいます。ここで打つのは Linux コマンドではなく SQL です。

  2. どんなデータベースがある？

    SHOW DATABASES;
    USE potchi;
    SHOW TABLES;
    よくある迷子：SQLの最後には ;（セミコロン）が必要です。忘れると -> が出て止まったように見えます。そのときは ; だけ打って Enter。

  3. ストアのテーブル（4つ）

    products

    商品

    • id 番号
    • name 商品名
    • price 価格
    • description 説明文
    • stock 在庫数
    • is_published 公開中か
    • created_at 登録日時

    orders

    注文（1回の購入につき1行）

    • id 注文番号
    • customer_name お客さんの名前
    • email / address 連絡先・住所
    • total_price 合計金額
    • status new / shipped
    • created_at 注文日時

    order_items

    注文の明細（買った商品ごとに1行）

    • id 番号
    • order_id どの注文か
    • product_id どの商品か
    • product_name 買ったときの商品名
    • unit_price 買ったときの値段
    • quantity 個数

    admin_users

    管理画面にログインできる人

    • id 番号
    • login_id ログインID
    • password_hash 暗号化したパスワード

  4. SELECT で取り出してみる

    • DESC products;

      テーブルの設計図（列の一覧）を見ます。

    • SELECT * FROM products;

      商品を全部、全列で表示します。

    • SELECT name, price FROM products WHERE price < 2000 ORDER BY price;

      2000円未満の商品を、安い順に表示します。

    • SELECT COUNT(*) FROM orders;

      これまでの注文の件数です。

  5. わざと怒られてみる

    みんなで1つのDBを使っているので、皆さんのアカウントにはデータを 消す権限 がありません。試してみましょう。

    DELETE FROM products;
    ERROR 1142 (42000): DELETE command denied to user '受講者ID'@'...' for table 'products'

    この「権限で守る」という考え方は、実際の現場でもとても大事です。確認できたら抜けましょう。

    exit
    exit

    2回 exit すると、MySQL → Linux → 自分のPC と、箱から順に出てきます。

クリア条件：SELECTで商品一覧が表示され、DELETEで怒られた。

A5M24

めんどうなので画面で見る

目安 15分SSHトンネル / GUIツール

MISSION毎回 ssh して mysql するのは大変。A5M2 に同じ道のりを自動でたどってもらう。

  1. 接続先を追加する

    A5M2 を起動し、メニューの「データベース」→「データベースの追加と削除」→「追加」→「MySQL/MariaDB（直接接続）」を選びます。

  2. 「SSH2トンネル」タブを先に設定する

    これが、さっき手で打った ssh の代わりになります。

    項目入れる値
    SSH2トンネルを使用するチェックを入れる
    SSH2 ホスト名サーバIP
    ポート番号22
    ユーザーID受講者ID
    秘密鍵ファイルC:\Users\（あなたの名前）\.ssh\potchi_key

  3. 「基本」タブを設定する

    こちらは、さっきの mysql -u ... -p の代わりです。

    項目入れる値
    ホスト名127.0.0.1（サーバの中から見たMySQL、という意味）
    ポート番号3306
    ユーザーID受講者ID
    パスワードMySQLのパスワード（講師から配布）
    データベースpotchi

    「テスト接続」を押して「接続に成功しました」と出たら OK。名前は「ぽちっとストア」などにしておきましょう。

  4. 中を見てみる

    左のツリーから products をダブルクリックすると、商品が表のように並びます。さっき黒い画面で見たのと同じデータです。

    上のメニューから SQL エディタを開いて、次のSQLを貼り付け、実行ボタンを押してみましょう。

    SELECT o.id, o.customer_name, oi.product_name, oi.quantity, o.status
FROM orders o
JOIN order_items oi ON oi.order_id = o.id
ORDER BY o.id DESC;
    JOIN って？ 「注文」と「注文の明細」は別々のテーブルです。order_id を手がかりに2つをつなげて、「誰が何を何個買ったか」を1つの表にしています。

クリア条件：A5M2 で products の中身と、JOIN の結果が見えた。

Python5

ストアを開店する

目安 20分仮想環境 / pip / flask run

MISSION自分のPCでECサイトを起動して、ブラウザでお店を開く。

  1. ソースのフォルダに移動する

    cd ~\Documents\potchi-store

  2. このアプリ専用の道具箱（仮想環境）を作る

    python -m venv .venv

    .venv というフォルダができます。ここにライブラリを入れていきます。

    仮想環境って？ GitHub にあるのは「自分たちが書いたソース」と「必要なライブラリの一覧表（requirements.txt）」だけ。ライブラリ本体は、各自がこの道具箱に取ってきます。PC全体を汚さないので、失敗しても .venv フォルダを消せば元通りです。

  3. 道具箱を開く（activate）

    .venv\Scripts\activate
    行の先頭に (.venv) が付いたら成功
    (.venv) PS C:\Users\you\Documents\potchi-store>
    赤い文字で「スクリプトの実行が無効」と出たら：次のコマンドを1回だけ打ってから、もう一度 activate してください。（自分のPCで、自分で作ったスクリプトの実行を許可する設定です）
    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
    毎回のおやくそく：ターミナルを開き直したら、(.venv) が消えます。アプリを動かす前に、もう一度 activate してください。

  4. 一覧表どおりにライブラリを取ってくる

    pip install -r requirements.txt
    ライブラリ役割
    FlaskWebアプリの本体。URLに応じて画面を返す
    PyMySQLPythonからMySQLにSQLを送る
    cryptographyMySQL 8 のログイン方式に必要な暗号処理
    python-dotenv.env から接続情報を読み込む

  5. DBへの通り道（SSHトンネル）を開く

    MySQLはインターネットに直接は出ていません。そこで ssh に「自分のPCの 13306 番を、サーバの MySQL につないでおいて」と頼みます。ターミナルの ＋ で 新しいタブ を開いて打ちます。

    ssh -i ~\.ssh\potchi_key -N -L 13306:127.0.0.1:3306 受講者ID@サーバIP

    何も表示されずに止まったように見えたら成功です。このタブは閉じずに、そのまま置いておきます。元のタブに戻って続けましょう。

    -L 13306:127.0.0.1:3306 の意味：「自分のPCの 13306 番に来たものを、サーバから見た 127.0.0.1（サーバ自身）の 3306 番に届ける」。A5M2 の「SSH2トンネル」も、裏でこれと同じことをしています。

  6. 接続情報（.env）を用意する

    ひな形をコピーして、VS Code で開きます。

    copy .env.example .env
    code .env

    中身をこう書き換えて保存します。

    DB_HOST=127.0.0.1
DB_PORT=13306
DB_USER=受講者ID
DB_PASSWORD=（MySQLのパスワード）
DB_NAME=potchi
SECRET_KEY=（好きな英数字を20文字くらい）
    .env は GitHub に上がらない：パスワードが書いてあるので、.gitignore で「上げないもの」に指定してあります。ソースと秘密は分けて持つ、が鉄則です。

  7. 開店！

    flask run --debug
     * Running on http://127.0.0.1:5000
Press CTRL+C to quit

    ブラウザで開いてみましょう。

    画面URL
    ストア（お客さん用）http://127.0.0.1:5000/
    管理画面http://127.0.0.1:5000/admin
    止めるとき：ターミナルで Ctrl + C。動いている間、このターミナルは使えないので、別の作業は新しいタブを開いて行います。

クリア条件：ブラウザに「ぽちっとストア」の商品一覧が表示された。

実戦6

売って、買って、届ける

目安 25分管理画面 → ストア → DB

MISSION自分の商品を出品し、隣の人の商品を買い、注文がDBに届くのを見届ける。

  1. 管理画面で出品する

    /admin にログイン（IDとパスワードは講師が当日案内します）。右上の「＋ 商品を登録」から、自分の名前入りの商品 を作りましょう。

    例：「山田の手作りクッキー」 1,200円 在庫10

  2. 管理画面からストアへ飛ぶ

    商品一覧の「ストアで見る」リンクを押すと、お客さんから見たその商品のページが開きます。管理画面とストアが同じデータを見ていることを確認しましょう。

  3. 隣の人の商品を買う

    DB はみんなで共有しているので、隣の人が出品した商品もあなたのストアに並んでいるはず。カートに入れて、名前・住所・メールを入れて「注文を確定する」。

    決済はありません：本物のクレジットカードは使いません。入力するのは架空の名前や住所で大丈夫です。

  4. 注文が届いたか確認する

    管理画面の「注文一覧」を開くと、誰かがあなたの商品を買った注文が並んでいます。注文を開いて「発送済みにする」を押してみましょう。

  5. A5M2 で裏側を確かめる

    画面でやったことが、DB にどう残ったかを見ます。

    SELECT o.id, o.customer_name, oi.product_name, oi.quantity, o.status, o.created_at
FROM orders o
JOIN order_items oi ON oi.order_id = o.id
ORDER BY o.id DESC
LIMIT 10;

    さっき「発送済み」にした注文の status が shipped になっていれば、画面とDBがつながっている証拠です。

  6. 逆向きもやってみる：SQLで値段を変える

    今度はDBを直接書き換えて、画面が変わるか見てみます。自分の商品の id を確認してから実行しましょう。

    UPDATE products SET price = 9800 WHERE id = （自分の商品のid）;

    ストアの画面を再読み込みすると……値段が変わっています。画面はDBの中身を映しているだけ、ということが体感できます。

    WHERE を忘れない：WHERE を付けずに UPDATE すると、全員の商品 の値段が変わります。実行する前に、指差し確認しましょう。

クリア条件：自分の商品が誰かに買われ、A5M2 でその注文が見えた。

BOSS7

自分のお店に改造して push

目安 15分git add / commit / push

MISSIONソースを少しだけ書き換えて、自分のGitHubに記録を残す。

  1. お店の名前を変える

    VS Code でフォルダを開き、templates/shop/base.html の「ぽちっとストア」を、好きな店名に書き換えて保存。--debug で起動しているので、ブラウザを再読み込みするだけで反映されます。

    code .

  2. 何が変わったか確認する

    サーバを止めずに、ターミナルの新しいタブを開いて打ちます。

    cd ~\Documents\potchi-store
    git status

    変更したファイルが赤く表示されます。.env が出てこないことも確認しましょう（.gitignore のおかげです）。

  3. 記録して、送る

    git add .
    git commit -m "店名を変更"
    git push
    コマンドたとえると
    git add送る荷物を箱に詰める
    git commit箱に封をして、ラベル（メッセージ）を貼る
    git pushGitHub に発送する

  4. GitHub で確認する

    自分のリポジトリを開くと、「店名を変更」というメッセージ付きで記録が増えています。

クリア条件：GitHub に自分のコミットが表示された。

あと 8 ステージ

全部クリアすると、「注文を確定する」ボタンの先で何が起きているか、説明できるようになっています。

困ったときは

エラーは「次に何をすればいいか」を教えてくれるメッセージです。まず赤い文字の最後の1行を読んでみましょう。

python と打つと Microsoft Store が開く

Windows の「設定」→「アプリ」→「アプリの詳細設定」→「アプリ実行エイリアス」で、python.exe と python3.exe をオフにしてから、ターミナルを開き直してください。

'python' は、内部コマンドまたは外部コマンド…として認識されていません

Python のインストール時に「Add python.exe to PATH」のチェックが外れていた可能性が高いです。インストーラをもう一度実行し、「Modify」から PATH に追加するか、アンインストールしてチェックを付けて入れ直してください。

ssh で Permission denied (publickey)
  • 受講者IDのつづりは合っていますか？
  • -i のあとの鍵ファイルの場所は合っていますか？ ls ~\.ssh で確認できます。
ssh で UNPROTECTED PRIVATE KEY FILE と出る

鍵ファイルを「他の人も読める」状態だと、ssh は使ってくれません。鍵ファイルを右クリック →「プロパティ」→「セキュリティ」で、自分以外のユーザーを外してください。わからなければ講師を呼んでください。

mysql で ERROR 1045 Access denied

ユーザー名かパスワードが違います。パスワードは画面に表示されないので、ゆっくり打ち直してみてください。

アプリ起動後、Can't connect to MySQL server と出る
  • SSHトンネルのタブを閉じていませんか？ 閉じていたら、ステージ5の「DBへの通り道」のコマンドをもう一度実行してください。
  • .env が DB_HOST=127.0.0.1、DB_PORT=13306 になっていますか？
  • PCがスリープすると、トンネルが切れることがあります。そのときも、トンネルを開き直せば直ります。
flask : 用語 'flask' は認識されません／ModuleNotFoundError

道具箱が開いていません。行の先頭に (.venv) が付いているか確認し、なければ activate してください。それでもダメなら pip install -r requirements.txt をもう一度。

.venv\Scripts\activate
Address already in use／ポート 5000 が使われている

別のターミナルで、すでにアプリが動いているかもしれません。そちらを Ctrl + C で止めるか、別の番号で起動します。

flask run --debug --port 5001
git push で 403 や Permission denied

講師のリポジトリに push しようとしている可能性があります。git remote -v で、origin が自分のユーザー名のURLになっているか確認してください。
